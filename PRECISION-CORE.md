# NIKO Precision Core 1.0 — prototype de recherche

Module JavaScript autonome, sans dépendance supplémentaire et sans réseau. Les droits et notices existants sont conservés. Ce n'est pas une validation médicale ni un audit de cybersécurité indépendant.

## Banc de référence
`npm run precision:reference -- protocol.json` évalue des paires référence/estimation synchronisées et indépendantes; les estimations rejetées sont null. Schéma strict, métrique angle_deg ou cadence_spm, critères fournis à l'avance par le responsable du protocole, maximum 100 000 paires, aucun identifiant individuel. Voir precision-fixture.json pour des données purement synthétiques. Le rapport donne biais, MAE, RMSE, écart type échantillon, limites d'accord descriptives de Bland–Altman (biais ±1,96 SD), couverture et rejet. Les limites ne sont pas un intervalle de confiance. Des mesures répétées par sujet nécessitent une analyse statistique adaptée, non fournie. Le test ne vérifie ni indépendance, ni calibration, ni provenance, ni pré-enregistrement effectif des critères. Un résultat meetsSpecifiedCriteria ne prouve aucune validité clinique. Code de sortie 2 si critères non atteints, 1 si entrée invalide.

## Export de session chiffré
Dans le journal, saisir une phrase secrète forte puis cliquer Exporter session chiffrée. Web Crypto AES-GCM 256, PBKDF2 SHA-256 600 000 itérations, sel et IV aléatoires, contrôle d'authenticité. Le mot de passe n'est pas conservé volontairement. Déchiffrement programmatique via decryptSession(envelope,password), pas encore d'interface de restauration; sans phrase secrète il n'existe pas de récupération. Le JSON simple et les autres exports restent non chiffrés. Cela ne protège pas la mémoire, les fichiers temporaires ou un navigateur compromis et ne prouve pas l'origine des données. HTTPS/localhost requis. Pas de stockage patient recommandé. Les limites de taille ne remplacent pas une revue de sécurité. Aucun test de pénétration indépendant réalisé.
